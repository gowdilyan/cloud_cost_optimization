Cloud Cost Forecasting Dashboard

This page goes with the cloud cost optimization project. It uses one year (2023) of daily cloud billing data to forecast next month's spend and to flag days when spend goes above the expected range. All the charts are interactive: hover for exact values, drag to zoom, double-click to reset, and click a legend item to show or hide it.

Contents: 1. Daily spend | 2. Forecast vs actual | 3. Spend alert | 4. Model comparison | 5. Savings calculator | 6. Grid search

1. Daily spend

Weekends (the grey bands) are about 24% cheaper than weekdays. Spend doesn't grow smoothly. It jumps in steps: up 16% in June, down 10% in August and up 29% in November. Use the buttons to split the spend by environment or provider, and the slider under the chart to zoom into a period.

2. Forecast vs actual

Each month was forecast using only the data before it. Pick a month from the dropdown. SARIMA, STL + ARIMA and Gradient Boosting are shown first, and the other models can be turned on in the legend. In normal months the best models are within about 6% per day. In June, August and November, when spend jumped, every model missed.

3. Spend alert

SARIMA, the final model, gives a 95% expected range for each day. A day above the range is flagged as an alert. In November and June the alert went off on the first day of the month, and in the normal months (October and December) there were no alerts. Pick a month from the dropdown.

4. Model comparison

Every model's MAPE (average daily error in %) for every month, with the averages for the normal months, the shift months and all nine months on the right. Hover over a cell for the exact value.

5. Savings calculator

Two of the recommendations are to scale down dev and staging on weekends and to focus cost reviews on prod. Move the sliders to see what they could save in a year. Scaling down 100% of the weekend spend is the maximum, since some non-prod work probably does need to run on weekends.

6. Grid search

The cross-validation MAPE for every combination of settings tried for Random Forest and Gradient Boosting, using January to November only. Use the dropdown to change the third setting.

Built with Plotly from 3_dashboard.ipynb. Data: Cloud Budget Dataset on Kaggle (synthetic).
